Investigating IPTV: A Security Deep-Dive

By Gabriel Guarnieri · DevSecOps & Cloud Security

Internet Protocol Television (IPTV) has grown rapidly as a content-delivery mechanism, but its underlying infrastructure often receives far less security scrutiny than traditional broadcast or OTT platforms. This article documents an investigation into the protocols, authentication mechanisms, and common misconfigurations found in IPTV deployments.

Background

IPTV delivers television content over IP networks using a combination of multicast streams, unicast VOD (Video on Demand), and live-channel feeds. Most residential deployments rely on an M3U playlist served over HTTP/HTTPS that references HLS (.m3u8) or MPEG-TS streams.

Investigation Methodology

The investigation used the following toolchain to enumerate, capture, and analyse traffic:

  • Wireshark / tshark — packet capture and stream dissection
  • mitmproxy — HTTPS interception and request replay
  • ffprobe / ffmpeg — stream validation and container analysis
  • Burp Suite CE — API surface mapping and authentication bypass testing
  • Python (Requests + m3u8) — playlist parsing and automated recon

Key Findings

1. Weak or Absent Authentication on Middleware APIs

Several deployments exposed administrative middleware endpoints without requiring valid credentials. A simple GET /api/streams request with an empty Authorization header returned the full channel list and stream URLs.

2. Cleartext Credentials in M3U Playlists

User credentials were embedded directly in stream URLs as query parameters (?username=foo&password=bar), making them trivially interceptable over HTTP or via referrer leakage. 

#EXTM3U
#EXTINF:-1 tvg-id="Channel1",Channel 1
http://iptv.example.com/live/username/password/channel1.m3u8

3. Insecure Direct Object References (IDOR) in VOD Endpoints

VOD asset IDs were sequential integers. Incrementing the stream_id parameter allowed access to content outside a subscriber's entitlement with no server-side validation.

Risk Summary

Finding Severity CVSS (approx.)
Unauthenticated middleware API Critical 9.1
Cleartext credentials in M3U URLs High 7.5
IDOR on VOD endpoints Medium 5.3
Unencrypted RTSP streams Medium 4.8

Recommendations

  1. Enforce token-based authentication (JWT or OAuth 2.0) on all middleware API endpoints.
  2. Migrate stream URL signing to short-lived HMAC tokens passed in headers, not query strings.
  3. Implement server-side entitlement checks for every VOD asset request.
  4. Enable TLS 1.2+ for all stream delivery paths; disable legacy RTSP over cleartext.
  5. Apply rate-limiting and anomaly detection on playlist/stream endpoints to detect credential stuffing.

Conclusion

IPTV platforms inherit many of the security challenges of web APIs while adding media-specific attack surfaces. The findings above are representative of issues encountered across multiple independent deployments and should serve as a baseline security checklist for operators conducting internal audits.

All testing was performed in a controlled lab environment or with explicit written permission from service operators. No production systems were accessed without authorization.
